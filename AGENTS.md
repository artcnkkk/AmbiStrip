# AGENTS.md

Инструкции для агентов в репозитории **LEDSetup**.

## Проект

Desktop-управление **одной** аналоговой RGB-лентой Smartbuy `SBL-RGBW-KIT-75` / Zengge LEDnetWF по BLE. **Имя в рекламе не стабильный ID** (может меняться); идентификация — BLE-адрес. Последний известный пример: имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`. Ранее фигурировало `LEDnetWF0200006B1AAC` (`020000` вместо `020008`) — устаревшая гипотеза точного имени, не константа продукта. Вся лента — **один общий цвет**. Не addressable, не per-LED, не per-section. Питание комплекта: `12V DC / 2A`, макс. `24W`. Вендорское приложение: **ZENGGE**.

GATT UUID (`Service 0000FFFF-…`, `Write 0000FF01-…`, `Notify 0000FF02-…`) **сверены** enumeration на этом контроллере. Кадры RGB (`0B 31`) и off (`0B 3B 24`) визуально подтверждены. CCCD (нужен ли для write), смысл notify JSON, seq/checksum, HSV, кадр `on`, лишние байты — TBD. Не слать chip type / LED count / addressable-кадры.

Язык общения с пользователем: **русский**, если пользователь не пишет по-английски. Имена устройств, UUID, термины протокола — как есть (English / hex).

## Шлюз SDD (обязательно)

Код фичи **не начинать** без утверждённой спеки.

1. Прочитать [`specs/template.md`](specs/template.md) и существующие спеки в [`specs/`](specs/).
2. Если спеки нет — создать папку `specs/NNN-kebab-case/spec.md` из шаблона, статус `draft`.
3. Остановиться и дождаться утверждения пользователем (`draft` → `approved`).
4. Реализовать **только** утверждённую спеку. Лишнего не придумывать. Если объём меняется — сначала обновить спеку, снова получить approval.

Статусы: `draft` | `approved` | `in-progress` | `done`.

Нумерация: три цифры, затем короткое имя (`001-ble-discovery-and-control`). Сценарии продукта: S1–S5 — см. [`specs/README.md`](specs/README.md).

## Безопасность BLE

Не слать непроверенные payload «наугад», если они могут быть вредны контроллеру (длинные/мусорные кадры, команды смены chip type / LED count / addressable-режимов). Сначала: открытый реверс Zengge/LEDnetWF + захват/проверка на устройстве. Неизвестные байты помечать TBD. UUID FFFF/FF01/FF02 на этом ките сверены; не утверждать TBD из [`docs/protocol-notes.md`](docs/protocol-notes.md).

ПО не должно «превышать» аппаратные ограничения комплекта (`12V` / `24W`); analog RGB нельзя превратить в per-pixel API.

## Объём и стиль реализации

- Одно устройство, локальный BLE, desktop. Цель — выбранный адрес (scan или `--address`). Без облака, мультиаккаунта и абстракций «на парк лент».
- Screen-sync (S5) — северная звезда, **не** первый срез. Сначала вертикальный кусок: найти → выбрать → подключить → задать цвет.
- Маленькие срезы. Стек не выбран, пока его не зафиксирует `approved`-спека.
- Не коммитить, пока пользователь явно не попросил.
- При реализации UI проверять поведение в приложении (или браузере, если UI веб) end-to-end, не только скриншотом.
