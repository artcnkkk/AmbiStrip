## Проблема / зачем

Терминальное меню (`003`) умеет всё нужное, но это не приложение для ежедневного пользования. Нужен **полный перенос** тех же действий в одно простое окно: устройство, цвет, вкл/выкл, GATT, настройки. Не отдельный пикер «поверх» меню.

## Пользовательский сценарий

**Дано:** Windows 10/11, Bluetooth, комплект Smartbuy `SBL-RGBW-KIT-75`. Цель — BLE-адрес. RGB `0B 31` и off `0B 3B 24` подтверждены.

**Когда:** пользователь запускает LEDSetup (окно, не пункты в PowerShell). Сканирует и выбирает ленту кликом, двигает цвет, включает/выключает, при необходимости смотрит GATT и меняет таймауты. Закрывает окно.

**Тогда:** вся полоса одним RGB; off гасит; линк жив, пока окно открыто; адрес/имя/связь видны в шапке; настройки и выбранное устройство те же файлы, что у меню.

## Scope

Всё, что было в терминальном меню `003`, в desktop-окне **по шагам**, не всё сразу:

- экран «лента»: scan всех реклам, карточки, `LEDnetWF` как подсказка, выбор, persist в `selected-device.json`; перед scan — disconnect;
- экран «цвет»: пикер (RGB 0–255) + пресеты, лента следует за мышью, throttle ~10 Гц; вкл (`on`, гипотеза) / выкл (`off`);
- GATT и настройки — отдельные панели, не на одном экране с пикером;
- шапка: адрес (ID), имя справочно, связь;
- connect при старте, если адрес сохранён; закрытие окна → disconnect.

Запуск: `ledsetup` и `ledsetup gui` открывают окно. Терминальное меню — `ledsetup menu`. Разовые `scan` / `gatt` / `on` / `off` / `color` не ломаем.

Write как сейчас (FF01). На ленту с пикера — только RGB `0B 31`, не HSV-кадр. Яркости отдельной нет.

Юнит-тесты без адаптера: RGB-кадр из цвета пикера, throttle, off/on кадры, `ledsetup` без аргументов не требует TTY-меню.

README: окно — основной запуск.

Стек: Python 3.11+, Bleak, окно на **WebView2** (HTML/CSS), код в `app/`. Не tkinter: его виджеты выглядят как Win32.

## Вне scope

- Screen-sync (`005`).
- Трей, `.exe`, облако, несколько лент.
- Addressable / per-LED / непроверенные кадры.
- Выкидывать CLI-подкоманды.

## Допущения по железу

- Идентификация: BLE-адрес (имя рекламы нестабильно). Пример last-seen: имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`
- Тип: analog RGB, один общий цвет
- GATT UUID FFFF/FF01/FF02 сверены на этом ките; не утверждать TBD из `docs/protocol-notes.md`
- Питание: `12V DC / 2A`, макс. `24W` — софт мощность не задаёт

## Критерии успеха

- [x] `ledsetup` открывает окно на Windows, без обязательного меню в терминале.
- [x] В окне доступны те же действия, что в меню: scan/выбор, connect, цвет, on, off, GATT, настройки.
- [x] Пикер меняет **всю** ленту RGB-кадром; HSV-протокол не шлётся.
- [x] Off гасит; on есть и подписан как гипотеза.
- [x] Два быстрых цвета — один BLE-connect, если линк жив.
- [x] Выбранный адрес и настройки переживают перезапуск.
- [x] `ledsetup menu` и `ledsetup color` / `off` работают.
- [x] Юнит-тесты без Bluetooth проходят.

## Заметки по реализации

Уточнение пользователя: «полный перенос с терминала в UI», простой приятный вид. `005` не входит.

- Два экрана (лента → цвет), WebView2 + HTML. Не tkinter.
- Throttle 0.1 с. Пикер HSV в браузере окна; write — `build_rgb_frame`.
- `BleSession` + asyncio в фоне; `pywebview` в главном потоке.
