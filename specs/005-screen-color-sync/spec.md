## Проблема / зачем

Цель продукта — атмосфера: лента за ноутбуком roughly повторяет то, что на мониторе. Пикер (`004`) даёт ручной цвет; этот срез добавляет **цикл «снимок экрана → один RGB → лента»**. Не ambilight по краям и не разные цвета слева/справа: железо — analog RGB, вся полоса одним цветом.

Реализацию этого среза **не начинать**, пока `004` не `approved` (лучше — не `done`): sync должен включать/выключаться в том же окне и слать цвет тем же путём, что пикер.

## Пользовательский сценарий

**Дано:** Windows 10/11, ноутбук с экраном, Bluetooth, комплект Smartbuy `SBL-RGBW-KIT-75`. Окно пикера из `004` умеет держать BLE и ставить сплошной RGB / off. Имя ленты нестабильно; цель — адрес.

**Когда:** пользователь в окне включает «синхронизация с экраном», смотрит видео или просто меняет картинку на мониторе, затем выключает sync.

**Тогда:**

- вся лента следует за **средним** цветом захваченного экрана (один RGB на всю полосу);
- задержка достаточна для атмосферы: сцена сменилась — лента заметно подхватывает, а не раз в много секунд;
- выключение sync останавливает захват; лента остаётся на последнем посланном цвете (или можно сразу off — зафиксировать в открытых вопросах);
- пикер в режиме sync не обязан конкурировать: либо блокируется, либо ручной цвет снова работает после выключения sync;
- ошибка захвата или BLE — сообщение в окне, sync останавливается, без подбора другого устройства.

## Scope

- Захват **одного** экрана ноутбука (по умолчанию основной монитор Windows).
- Из кадра считается **один** средний RGB (даунскейл/прореживание допустимы). Не карта пикселей ленты, не зоны, не «только рамка», если это не понадобится для скорости — в этом срезе достаточно среднего по кадру.
- Периодическая отправка на ленту тем же BLE-write RGB `0B 31`, что пикер. Throttle: не чаще, чем выдержит линк и глаз (ориентир как в `004`, ~10 Гц потолок; ниже — нормально). Off по-прежнему отдельной кнопкой / кадром `0B 3B 24`.
- В UI: тумблер «экран → лента» вкл/выкл. Пока sync включён, видно что-то вроде «идёт захват» и текущий усреднённый RGB (превью).
- Один комплект, один линк, тот же persist адреса. Новых кадров протокола нет. HSV / chip type / LED count / addressable не слать.
- Юнит-тесты без адаптера и без живого экрана: функция «кадр (маленький массив пикселей) → средний RGB»; чёрный кадр → `(0,0,0)`; одноцветный красный → около `255,0,0`; sync выкл → цикл не пишет.
- README: как включить sync, что лента — один цвет, не периметр.
- Права/доступ к экрану на Windows: если ОС/политики запрещают захват — понятная ошибка, не молчаливый чёрный цвет.

Стек захвата экрана в draft **не** фиксируем. Код в `app/`, Python 3.11+, Bleak как в `001`/`004`.

## Вне scope

- Повторение пикера: выбор цвета мышью — спека `004`, здесь только sync.
- Настоящий ambilight: разные цвета по краям, несколько лент, HDMI-боксы, TV.
- Игры с anti-cheat / эксклюзивный полноэкранный захват как обязательное требование (если конкретная игра не захватывается — документировать, не подбирать эксплойты).
- Калибровка под глаз, HDR tonemap, выбор «только яркие пиксели» как обязательная часть (можно позже).
- Трей, `.exe`, облако, несколько устройств.
- Изменение GATT/кадров RGB и off.

## Допущения по железу

- Идентификация: BLE-адрес (имя рекламы нестабильно). Пример last-seen: имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`
- Тип: analog RGB, один общий цвет — средний цвет экрана **целиком** красится в этот один RGB
- GATT UUID FFFF/FF01/FF02 сверены на этом ките; не утверждать TBD из `docs/protocol-notes.md`
- Питание: `12V DC / 2A`, макс. `24W` — софт мощность не задаёт

## Критерии успеха

- [ ] Тумблер sync вкл: лента визуально следует за заметной сменой картинки на экране (например яркий красный слайд → полоса краснеет).
- [ ] Тумблер выкл: захват прекращается, новых цветов с экрана нет.
- [ ] Вся полоса одним цветом; нет API секций/пикселей.
- [ ] Задержка приемлема для атмосферы (не «слайд уже давно другой, лента ещё думает секунды»). Точный SLA в мс не фиксируем до прогона на этом ноутбуке.
- [ ] Нет устройства / нет захвата / BLE отвалился — текст в окне, sync не крутится вхолостую.
- [ ] Юнит-тесты усреднения кадра без экрана и без BLE проходят.
- [ ] Пикер и CLI из `003`/`004` не сломаны.
