## Проблема / зачем

Цель продукта — атмосфера: лента за ноутбуком roughly повторяет то, что на мониторе. Пикер (`004`) даёт ручной цвет; этот срез добавляет **цикл «снимок экрана → один RGB → лента»**. Не ambilight по краям и не разные цвета слева/справа: железо — analog RGB, вся полоса одним цветом.

Зависимость закрыта: `004` уже `done`. Sync включается в том же окне и шлёт цвет тем же RGB-кадром, что пикер. Плюс те же действия в терминальном меню и разовой CLI-команде.

## Пользовательский сценарий

**Дано:** Windows 10/11, ноутбук (возможно несколько мониторов), Bluetooth, комплект Smartbuy `SBL-RGBW-KIT-75`. Окно пикера из `004` умеет держать BLE и ставить сплошной RGB / off. Имя ленты нестабильно; цель — адрес.

**Когда:** пользователь включает «синхронизация с экраном» в окне, в `ledsetup menu` или командой `ledsetup sync`, смотрит видео или меняет картинку, затем выключает sync (тумблер / клавиша / Ctrl+C / истек `--seconds`).

**Тогда:**

- окно **шире**, чем в `004` (там ~480px): на экране цвета хватает места пикеру и блоку sync, без смены визуального языка (тёмная тема, карточки, круглые кнопки);
- экран «какая лента?» **не обрастает** sync, монитором, превью RGB — по-прежнему только scan и карточки;
- вся лента следует **оттенку** среднего цвета контента выбранного монитора на **полной яркости** (один RGB на всю полосу; тусклое среднее не делает полосу тусклой);
- letterbox: равномерные чёрные полосы по краям кадра отбрасываются; среднее — по оставшейся области; тёмные пиксели **внутри** картинки считаются;
- задержка достаточна для атмосферы: сцена сменилась — лента заметно подхватывает, а не раз в много секунд;
- выключение sync останавливает захват; лента **остаётся на последнем посланном цвете**;
- пока sync включён, пикер и пресеты **заблокированы**; ручной цвет снова после выключения sync;
- кнопка Off в режиме sync **гасит кадром off, но цикл не останавливается** — следующий RGB с экрана снова зажигает ленту;
- ошибка захвата — сообщение и стоп. Краткий обрыв BLE на **том же** адресе (WinRT `Unreachable` на FF01) — reconnect и продолжить; если линк не поднялся — сообщение и стоп, другое устройство не брать.

## Scope

- Захват **одного** выбранного экрана. В окне — список мониторов Windows и выбор. Сохранённый выбор переживает перезапуск (настройки приложения, не файл BLE-адреса).
- Из кадра: сначала обрезка letterbox (чёрные поля по краям), затем **один** средний RGB по остатку, затем яркость до максимума: `max(R,G,B)=255` (HSV V=1, H/S те же). `(0,0,0)` остаётся off, в белый не раздуваем. Слайдера яркости нет. Даунскейл/прореживание допустимы. Не карта пикселей ленты, не зоны, не «рамка ambilight». Превью в окне — уже бустнутый RGB (то, что ушло на ленту).
- Периодическая отправка тем же BLE-write RGB `0B 31`, что пикер. Throttle: ориентир как в `004`, ~10 Гц потолок; ниже — нормально. Off — кадр `0B 3B 24`. На FF01 (есть `write` и `write-without-response`) для held/sync — **write-without-response**: write с response на этой частоте даёт `characteristic 0016: Unreachable` (handle `0x0016` = 22 = FF01).
- **Окно, ширина:** native-окно шире текущего `480×760`, ориентир **720–840px** по ширине, высота того же порядка (не maximize, не resizable-дашборд). CSS `max-width: 480px` снять: второй экран использует ширину. Стиль тот же, что в `004` (цвета, шрифт, карточки, кнопки-пилюли). Не новый визуальный язык.
- **Экран 1 («какая лента?»):** те же фичи, что в `004` — заголовок, пояснение про адрес, «Найти ленту», карточки. **Нет** тумблера sync, выбора монитора, превью среднего RGB, on/off ленты. Контент не растягивать на всю новую ширину «чтобы заполнить»: узкая колонка по центру (как сейчас), чтобы не выглядело пустым и не провоцировало набить кнопками.
- **Экран 2 («цвет»):** сюда все новые контролы. Ширину тратить на раскладку: пикер (+ пресеты, вкл/выкл) и рядом блок sync (тумблер «экран → лента», выбор монитора, статус «идёт захват», превью усреднённого RGB). Пока sync включён — пикер/пресеты не принимают цвет. GATT и настройки — по-прежнему оверлеи в шапке, не на экран 1.
- **Меню:** пункт sync; цикл, пока пользователь не остановит клавишей (аналог Ctrl+C). После остановки — последний цвет.
- **CLI:** `ledsetup sync`. Цикл до Ctrl+C **или** `--seconds N`, что наступит раньше. Без `--seconds` — только Ctrl+C. Флаг монитора (индекс/id из списка Windows). Цель — сохранённый адрес или `--address`, как у остальных write-команд.
- Один комплект, один линк, тот же persist адреса. Одновременно одно соединение: открытое окно и `ledsetup sync` в другом процессе не обязаны делить адаптер. Новых кадров протокола нет. HSV / chip type / LED count / addressable не слать.
- Юнит-тесты без адаптера и без живого экрана: кадр → обрезка letterbox → средний RGB; чёрный кадр → `(0,0,0)`; одноцветный красный → около `255,0,0`; красное с чёрными полосами сверху/снизу → около красного, не серого; тусклый красный после буста → около `(255,0,0)`; чёрный после буста остаётся `(0,0,0)`; sync выкл → цикл не пишет; `--seconds` ограничивает длительность (без реального BLE).
- README: как включить sync в окне, меню и CLI; что лента — один цвет, не периметр; как выбрать монитор; sync шлёт оттенок экрана на полной яркости.
- Права/доступ к экрану на Windows: если ОС/политики запрещают захват — понятная ошибка, не молчаливый чёрный цвет.

Стек захвата экрана в draft **не** фиксируем. Код в `app/`, Python 3.11+, Bleak как в `001`/`004`. Окно — то же WebView2, что в `004`.

## Вне scope

- Повторение пикера: выбор цвета мышью — спека `004`; здесь пикер на время sync только блокируется.
- Настоящий ambilight: разные цвета по краям, несколько лент, HDMI-боксы, TV.
- Игры с anti-cheat / эксклюзивный полноэкранный захват как обязательное требование (если конкретная игра не захватывается — документировать, не подбирать эксплойты).
- Калибровка под глаз, HDR tonemap, «только яркие пиксели» (игнор тёмных **внутри** кадра), слайдер яркости. Фиксированный V=max после среднего — в scope, не калибровка.
- Трей, `.exe`, облако, несколько устройств сразу.
- Изменение GATT/кадров RGB и off.
- Фоновый `sync start` / отдельный демон.
- Редизайн с нуля, светлая тема, третий «экран настроек sync», набивание экрана 1 новыми кнопками «чтобы ширина не пустовала».

## Допущения по железу

- Идентификация: BLE-адрес (имя рекламы нестабильно). Пример last-seen: имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`
- Тип: analog RGB, один общий цвет — оттенок среднего **контента** экрана на полной яркости (PWM, max канал 255; отдельного brightness-кадра нет)
- GATT UUID FFFF/FF01/FF02 сверены на этом ките; не утверждать TBD из `docs/protocol-notes.md`
- Питание: `12V DC / 2A`, макс. `24W` — софт мощность не задаёт

## Критерии успеха

- [ ] Тумблер / пункт меню / `ledsetup sync` вкл: лента визуально следует за заметной сменой картинки на **выбранном** мониторе (яркий красный слайд → полоса краснеет).
- [ ] Выключение (тумблер, клавиша в меню, Ctrl+C или конец `--seconds`): захват прекращается; лента остаётся на последнем RGB, не гасится сама.
- [x] Letterbox: чёрные поля по краям не уводят среднее в серый, если контент цветной. (юнит-тест кадра)
- [x] В окне можно выбрать монитор; выбор сохраняется; в CLI тот же выбор или явный флаг.
- [x] Пока sync включён, пикер и пресеты не меняют цвет; Off шлёт off, но не останавливает цикл (лента снова зажигается со следующего кадра экрана).
- [x] Вся полоса одним цветом; нет API секций/пикселей.
- [ ] Задержка приемлема для атмосферы. Точный SLA в мс не фиксируем до прогона на этом ноутбуке.
- [x] Нет устройства / нет захвата / BLE не поднялся повторно — текст, sync не крутится вхолостую.
- [x] Юнит-тесты усреднения и letterbox без экрана и без BLE проходят.
- [x] Тусклый красный после буста → около `(255,0,0)`; `(0,0,0)` не становится белым.
- [x] Пикер и CLI из `003`/`004` не сломаны.
- [x] Окно заметно шире, чем в `004`; экран 1 без sync/монитора, контент не размазан на всю ширину; экран 2 держит пикер и sync в одном стиле, без визуального разлома.

## Заметки по реализации

- Захват: `mss`. Монитор идентифицируется геометрией `left,top,WxH`; если сохранённого нет — основной Windows (обычно `left=top=0`) и запись в настройки.
- BLE: `mss`/захват не при чём, если sync уже слал цвет. Unreachable на handle `0016` — stale GATT. Один reconnect того же адреса на write, затем стоп.
- Кадр даунскейлится (длинная сторона ~160), затем letterbox (каналы ≤ 16 по всему ряду/столбцу), затем среднее, затем `boost_max_value` (V=1). Throttle 0.1 с, кадр RGB `0B 31`. Пикер не бустится.
- Окно `800×760`. Экран 1 — узкая колонка ~420px. Экран 2 — сетка пикер | панель sync.
- CLI: `ledsetup sync [--seconds N] [--monitor INDEX|id]`. Меню: пункт 8, Enter — стоп.
