## Проблема / зачем

Сейчас LEDSetup — набор разовых команд (`scan`, `gatt`, `color`, `on`, `off`). Каждая команда сама подключается и отключается. Для обычного пользования это не приложение: нет меню, нет настроек, смена цвета каждый раз ждёт connect.

Нужен **интерактивный терминальный ап**: запустил → видишь пункты → выбираешь устройство → задаёшь цвет / вкл / выкл, не выходя в оболочку. Одноразовые CLI-команды остаются для скриптов.

Это не GUI-окно и не screen-sync. Это «полноценный ап в терминале» на уже проверенном BLE/протоколе.

## Пользовательский сценарий

**Дано:** Windows 10/11, Bluetooth включён, комплект Smartbuy `SBL-RGBW-KIT-75` в эфире. Имя в рекламе нестабильно; цель — BLE-адрес. Разовые команды `ledsetup scan` / `color` уже работают. Терминал интерактивный (PowerShell / Windows Terminal).

**Когда:** пользователь запускает `ledsetup` без подкоманды. В шапке видит выбранное устройство (если есть) и статус связи. Через меню: сканирует и выбирает ленту, подключается, ставит цвет пресетом или своим RGB, гасит ленту, при необходимости смотрит GATT и меняет таймауты. Выходит пунктом «Выход».

**Тогда:**

- приложение остаётся в цикле меню, пока пользователь не выйдет;
- цвет и off меняют **всю** ленту одним RGB, как уже подтверждено кадрами `0B 31` / `0B 3B 24`;
- пока меню открыто, BLE-линк **удерживается** после первого успешного connect (повторный цвет не ждёт 30 с connect заново);
- настройки (таймауты и т.п.) сохраняются между запусками;
- выбранный адрес по-прежнему в `%LOCALAPPDATA%\ledsetup\selected-device.json`;
- без TTY (`ledsetup | …`) интерактив не стартует: подсказка запустить в терминале или воспользоваться подкомандами.

## Scope

- Запуск **без подкоманды** (`ledsetup`) открывает интерактивное текстовое меню. Подкоманды `scan` / `gatt` / `on` / `off` / `color` **не ломаем**.
- Шапка на каждом экране: адрес (ID), last-seen имя (справочно, не ID), статус «не выбрано / не подключено / подключено».
- Главное меню (номера + ввод):
  1. Сканировать и выбрать устройство (как `scan`: все рекламы, `*` у префикса `LEDnetWF`, выбор номером; адрес сохраняется).
  2. Подключить / отключить (явный connect/disconnect выбранного адреса).
  3. Цвет… (подменю).
  4. Включить (`on`, в UI пометить как гипотеза — на ките не проверяли).
  5. Выключить (`off`, подтверждён).
  6. GATT (перечисление, как сейчас).
  7. Настройки…
  0. Выход (disconnect, если линк был, затем процесс завершается).
- Подменю цвета — **один** общий цвет всей полосы:
  - пресеты: красный `255 0 0`, зелёный `0 255 0`, синий `0 0 255`, белый `255 255 255`;
  - свой RGB: три целых 0–255;
  - назад.
- Пока сессия меню жива: после успешного connect повторные `color` / `on` / `off` / GATT идут в **тот же** `BleakClient`, без нового connect на каждый кадр. Потеря линка → статус «не подключено» и понятное сообщение, без автоподбора другого устройства.
- Настройки, файл `%LOCALAPPDATA%\ledsetup\settings.json` (в тестах путь подменяемый):
  - таймаут scan (секунды, по умолчанию как сейчас 10);
  - таймаут connect (секунды, по умолчанию как сейчас 30);
  - подробный дамп GATT после write: да/нет (в меню по умолчанию **нет**, чтобы не засорять экран; разовые CLI-команды печатают как сейчас);
  - пункт «сбросить выбранное устройство» (удалить persist адреса).
- Ошибки BLE / «устройство не выбрано» / пустой scan — текст на экране, возврат в меню, код процесса 0 пока пользователь сам не выйдет (кроме фатального старта без TTY).
- Юнит-тесты без адаптера: разбор пунктов меню, валидация RGB, load/save настроек, «без TTY → не входить в цикл», удержание сессии на моке клиента (write дважды без второго connect).
- Документация запуска в корневом README: `ledsetup` = приложение; подкоманды = скрипты.

Стек языка/BLE как в `001`: Python 3.11+, Bleak, код в `app/`. Библиотеку TUI в draft **не** фиксируем: достаточно нумерованных экранов в том же терминале.

## Вне scope

- GUI-окно, системный трей, мышиный color picker (полный S4).
- Screen-sync / захват экрана (S5).
- Несколько одновременных устройств, облако, аккаунты.
- Addressable / per-LED / per-section, chip type, LED count, непроверенные кадры.
- HSV-кадр `0B 3B A1` в меню (гипотеза; остаётся только у CLI `--hsv`).
- Слайдеры, мышь, полноэкранный TUI-фреймворк как обязательная часть этого среза.
- Упаковка в `.exe`, коммит (пока не попросили).

## Допущения по железу

- Идентификация: BLE-адрес (имя рекламы нестабильно). Пример last-seen: имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`
- Тип: analog RGB, один общий цвет
- GATT UUID FFFF/FF01/FF02 сверены на этом ките; не утверждать TBD из `docs/protocol-notes.md`
- Write только в characteristic по тем же правилам, что сейчас (FF01, иначе единственный writable; никогда «первый попавшийся»).
- Кадры RGB и off не менять. `on` — гипотеза, слать только по явному пункту меню.
- Питание комплекта: `12V DC / 2A`, макс. `24W` — софт мощность не задаёт.

## Критерии успеха

- [x] `ledsetup` без аргументов в интерактивном терминале показывает шапку и главное меню.
- [x] Можно выбрать устройство из scan, задать пресет и свой RGB, выключить ленту, не возвращаясь в PowerShell между шагами.
- [x] Два цвета подряд в одной сессии не открывают второй BLE-connect, если линк жив.
- [x] Настройки таймаутов переживают перезапуск; сброс устройства заставляет снова выбрать адрес.
- [x] Разовые `ledsetup scan` / `color` / `off` работают как в спеках `001`/`002`.
- [x] Не-TTY без подкоманды не зависает на `input`, а объясняет, что делать.
- [x] Юнит-тесты без Bluetooth проходят.
- [x] Нет API «пиксель N» / секций; HSV из меню не шлётся.

## Открытые вопросы

- Нужен ли отдельный пункт «яркость», или достаточно RGB (предложение спеки: **достаточно RGB**, отдельной яркости нет).
- Держать ли линк при уходе в «Сканировать» (предложение: перед scan **отключить**, Windows часто не сканирует нормально с открытым клиентом).
