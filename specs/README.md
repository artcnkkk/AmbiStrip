# Спецификации (SDD)

Код фичи появляется **только** после того, как пользователь утвердил спеку. Черновики живут здесь; шаблон — [`template.md`](template.md).

## Как добавить спеку

1. Взять [`template.md`](template.md).
2. Создать папку `specs/NNN-kebab-case/` (следующий свободный номер, три цифры).
3. Положить `spec.md` со статусом `draft`.
4. Связать спеку со сценариями S1–S5 (таблица ниже).
5. Дождаться ответа пользователя: утверждение или правки. **Не** писать код приложения в статусе `draft`.

Имя папки — короткое, на английском (`001-ble-discovery-and-control`). Текст спеки — на русском; идентификаторы железа и UUID — как есть.

## Жизненный цикл

```
draft → (пользователь утверждает) → approved → in-progress → done
```

| Статус | Кто ставит | Что значит |
|--------|------------|------------|
| `draft` | агент / автор | Черновик. Реализации нет. |
| `approved` | **пользователь** | Можно кодить ровно этот scope. |
| `in-progress` | агент при старте работы | Идёт реализация утверждённого текста. |
| `done` | агент после приёмки среза | Критерии успеха выполнены. |

Если scope меняется после approval — вернуть спеку в `draft` (или явно переутвердить правки), не «тихо» расширять код.
