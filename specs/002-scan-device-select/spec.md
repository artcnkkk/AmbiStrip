## Проблема / зачем

Рекламируемое BLE-имя контроллера **меняется** и не годится как идентификатор. Срез 001 искал одно зашитое имя (`LEDnetWF0200086B1AAC` / устаревшее `LEDnetWF0200006B1AAC`). Нужно: список эфира → выбор пользователем → дальше `gatt` / `color` / `on` / `off` ходят на **выбранный адрес**.

## Пользовательский сценарий

**Дано:** Windows 10/11, Bluetooth включён, один аналоговый RGB-комплект Smartbuy `SBL-RGBW-KIT-75` в эфире. Имя в рекламе может быть `LEDnetWF…` или другим; стабилен **BLE-адрес**. Последний известный пример (не константа продукта): имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`.

**Когда:** пользователь запускает `ledsetup scan`, видит список, выбирает устройство (номер в промпте или флаг). Затем `gatt` / `color` / `on` / `off`.

**Тогда:**

- scan печатает **все** видимые BLE-рекламы, помечает совпадения префикса `LEDnetWF` (подсказка, не замок);
- выбор сохраняется в локальный файл (ключ — адрес; имя — справочно);
- команды, которым нужно устройство, используют сохранённый адрес либо `--address`;
- если выбора нет и `--address` не передан — понятная ошибка: сначала `scan` или флаг.

## Scope

- Только CLI в `app/` (Python, Bleak). Одно соединение за раз, без GUI.
- `ledsetup scan`: список всех реклам, подсветка `LEDnetWF*`; сортировка — сначала совпадения префикса.
- Выбор: интерактивный номер **и/или** флаги `--index` / `--address` / `--name` (без промпта; для скриптов и не-TTY).
- Файл последнего выбора: каталог пользователя Windows (`%LOCALAPPDATA%\ledsetup\`), адрес обязателен, имя last-seen.
- `gatt` / `on` / `off` / `color`: цель = сохранённый адрес или `--address`; без цели — ошибка, не поиск по зашитому имени.
- Префикс `LEDnetWF` — hint/filter default для подсветки. Пользователь может выбрать **любое** устройство из списка (один линк). Не слать chip-type / LED count / addressable.
- Юнит-тесты без адаптера: разбор флагов, выбор из списка, load/save, ошибка «не выбрано».
- Документы: имя ≠ стабильный ID; пример last-seen, не константа. `AGENTS.md`, hardware rule, README, `docs/protocol-notes.md`.

Стек как в `001`: Python 3.11+, Bleak, CLI, `app/`.

## Вне scope

- GUI-picker, трей, pairing UI.
- Облако, аккаунты, несколько одновременных подключений.
- Screen-sync (S5).
- Смена протокола / новые кадры / addressable API.
- Упаковка в `.exe`, коммит (пока пользователь не попросил).

## Допущения по железу

- Тип: analog RGB, один общий цвет; выходы `+ / R / G / B`
- Питание: `12V DC / 2A`, макс. `24W` — софт не «превышает»
- Идентификация: **BLE-адрес**. Имя рекламы нестабильно.
- Пример last-seen (не lock): имя `LEDnetWF0200086B1AAC`, адрес `E4:98:BB:6B:1A:AC`
- GATT на этом ките сверены: FFFF / FF01 / FF02 — см. `docs/protocol-notes.md`
- Не слать непроверенные chip-type / LED count / pixel-buffer

## Критерии успеха

- [x] `scan` показывает все рекламы; строки с префиксом `LEDnetWF` явно помечены; переименованное устройство без этого префикса **видно**.
- [x] Интерактивный ввод номера сохраняет адрес; `--index` / `--address` / `--name` выбирают без промпта (взаимоисключающие).
- [x] Не-TTY без флага выбора — ошибка с подсказкой флагов, а не «тихо взять первое LEDnetWF».
- [x] `gatt` / `on` / `off` / `color` не зависят от точного имени `LEDnetWF0200086B1AAC` / `LEDnetWF0200006B1AAC`.
- [x] Нет сохранённого адреса и нет `--address` → код ≠ 0 и текст про `scan` или `--address`.
- [x] Юнит-тесты без BLE-адаптера проходят.
- [x] Документы: имя не ID; адрес — ID; last-seen как пример.

Живой `scan` на адаптере пользователь ещё не прогонял после этой спеки — логика покрыта тестами с фиктивным списком.

## Заметки по реализации

Утверждение — явная просьба пользователя реализовать это в том же чате (имя нестабильно → выбор при scan). Статус сразу `in-progress`.

- Persist: JSON `%LOCALAPPDATA%\ledsetup\selected-device.json` (`address`, `name`). Для тестов путь можно подменить.
- `scan --address`: сохранить адрес даже если в этом прогоне рекламы не было (адрес известен).
- `scan --name`: точное имя из текущего списка; несколько совпадений → ошибка, нужен `--address`.
- Подключение `gatt`/write — по адресу, без повторного поиска «первого LEDnetWF».
- Кадры протокола не менять.

## Как утвердить

Пользователь в этом чате попросил реализовать срез сейчас. Спека пишется сразу как утверждённый узкий CLI-срез.
